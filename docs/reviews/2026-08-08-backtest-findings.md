# 历史回放验证 — 首轮结果（2026-08-08）

10 个 BTC-USD 历史窗口，point-in-time 回放 + 事后打分。原始决策见
`2026-08-08-backtest-replays.jsonl`，工具在 `tradingagents/backtest/`。

## 方法与其边界

**能重建的**：K 线、资金费率、持仓量、三个多空比 — 全部来自 Binance Vision 的
带日期归档（5 分钟粒度），加上 taker 量比（用 K 线的 taker buy volume 精确重建）。

**不能重建的**：新闻、Reddit、快讯中继。RSS 无归档；GDELT 对本机出口 IP 限流、
Wayback 502、付费新闻 API 需要 key。所以回放**只选 market analyst**，测的是
`selected_analysts=["market"]` 这个配置，不是三分析师的生产配置。

**模型污染**：已实测排除。Gemini 3.1 Pro 知识截止 2025-01，对 2026 年的窗口
明确回答 "I DO NOT KNOW"。

**泄漏防护**：`close_time <= cutoff` 才可见（截止时刻正在形成的那根 K 线不算），
且 `_http_get` 在回放期间被替换为抛异常 — 任何残留的实时取数会硬失败而不是
悄悄污染 prompt。`tests/test_backtest_pit.py` 覆盖这两条不变量。

## 发现

### A. 风控闸门对市价单不检查止损方向（安全缺口，最重要）

`tradingagents/futures/risk_gate.py:284`：

```python
# 4) Stop on the correct side of entry. Entry is optional (market);
# only enforce when both stop and entry are set.
if decision.entry_price is not None:
```

`entry_price is None`（市价单）时整条 `stop_wrong_side` 规则被跳过。本轮 7 笔
方向性决策里 5 笔是市价单，其中 2026-02-05 那笔真的产出了**做空但止损放在
入场价下方**（价格 70279，止损 69200），**闸门放行了**（`gate_passed=True`）。

后果：该仓位的保护单要么被交易所拒（`-2021 Order would immediately trigger`
类），留下裸仓；要么立即成交把仓位平掉。无论哪种，意图中的保护都不存在。

根因是时序：图的顺序是 PM → Risk Gate → Mark Price → Executor，闸门跑在拿到
mark price 之前，所以市价单在闸门眼里没有可比较的参考价。修法二选一 ——
把 mark price 取数前移到闸门之前，或让闸门自己为市价单取一次参考价。

**这是 618 个单测和 testnet 实弹验收都没暴露的缺口。**

### B. 明显的做空偏向

7 笔方向性决策里 6 笔做空、1 笔做多。样本窗口按后续走势是 5 涨 5 跌平衡的，
所以这不是行情决定的。整体 +3.41R 里，5 笔做空贡献 +1.91R，唯一一笔做多
贡献 +1.50R —— 做空胜率 2/5，做多 1/1。样本太小不能定论，但方向分布本身
（6:1）已经偏离随机，值得在攒更多样本时盯住。

### C. 止损相对波动率太紧

止损距入场 1.30%–2.95%，而止盈距入场 2.3%–6.1%。BTC 小时级波动经常超过 2%。

典型案例 2026-06-18：做空 63967，止损放在 1.30% 外的 64800。方向判断是对的
（BTC 在随后一周从 62924 跌到 59771），但止损先被打掉，最大有利波动只有
1.92%，从未接近 3.9% 外的止盈。

这与 2026-06-02 那笔真实决策是同一类问题（那笔是限价挂在市价上方 2.8% 等
反弹，差 0.99% 没成交，然后行情按预测方向走完）：**分析层的方向质量好于
成交层的战术质量。**

### D. 同一窗口重跑会得到不同决策

2026-01-29 跑了两次：一次止损 91200 / 止盈 82000，一次 89150 / 85800。方向
一致，价位不同。这意味着单次回放结果不可复现，任何评估都需要同窗多次采样
才能把 LLM 方差和真实信号分开。

### E. 震荡市里选择不开仓 —— 正确行为

3 个 Flat 全部落在低波动窗口（后续 7 日 −0.84% / +1.99% / −0.69%）。没有
出现"为了交易而交易"。

### F. 仓位比例字段已修好

2026-06-02 那次真实决策的 `position_size_pct` 是 10%（散文里却写"低于 1% 上限"），
被闸门拦下。本轮 10 个窗口无一复现，取值都在 0.25%–0.5%，schema description
的修复生效了。

## 建议下一步

1. 修发现 A（安全缺口，mainnet 前置）。
2. 发现 C 的止损宽度：让 PM 用 ATR 的倍数而不是拍百分比。
3. 同窗多次采样（发现 D），再谈胜率是否有意义。
4. 新闻/舆情通道从今天起做**前向归档**（每天存一份 RSS 快照），几个月后就有
   了可回放的舆情历史；这是唯一能把回测扩到三分析师配置的路。
